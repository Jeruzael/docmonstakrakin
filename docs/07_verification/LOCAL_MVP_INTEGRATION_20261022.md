## Integrated behavior

1. Discovery uses one catalog-normalized, wizard-aware required-gate projection in the dashboard and next action. Its visible percentage includes a numerator, denominator and formula; stored 70/40 defaults are no longer reported as measurements. The known legacy 21/20 coverage defect is repaired through metadata restoration, without clamping.
2. Reviewer setup exposes aggregate diagnostics and actionable session recovery. No roster values, credentials or default identities are exposed. Evidence person bindings remain operator assertions and require a submitter distinct from the Security Officer and Lead Architect reviewers.
3. Verification sessions preserve exact task/criteria snapshots, commit/build/environment, evidence bytes and digests, immutable submission and distinct-person decisions. Expected-reviewer binding prevents confirmations from silently moving to a changed session. Lists contain summaries; selected detail is fetched separately. All mutation acknowledgements establish a version floor before canonical reload.
4. Ordinary projects can create and edit bounded snapshot-owned documents through server-generated IDs and virtual display paths. Creation/update have distinct audit contracts, version/digest CAS, durable request IDs and atomic rollback. The canonical self-project retains its original filesystem registry and controlled workflow.
5. Explicit release scopes exclude unrelated future tasks. The dashboard distinguishes scoped lifecycle records and locally reviewed evidence from security assurance and production release readiness. A status-only legacy release check cannot satisfy Gate 3: authenticated production acquisition remains unavailable. Local review never opens release signoff.
6. Managed content and verification history have explicit portable-package fields. Public integrity hashes cannot grant authority. Imported verification is preserved only in `UNTRUSTED_IMPORTED_HISTORY` archives; active sessions are cleared and whole-store capacity is checked before application. Absent optional fields preserve legacy canonical hash inputs.

No dependency or lockfile change is needed. Canonical WBS, historical receipts, operational trust and identity roots, quorum, the 14 privileged-route denials, disabled live agents, Gate 7 execution and release promotion remain unchanged.

## Candidate admission limits and residual risks

Verification retention is capped at 100 active-plus-archived sessions per project, 500 total, 1 MiB compact JSON per session, 8 MiB per project and 32 MiB total, including retained duplication and archive overhead; at most 100 archive batches. Rejection is explicit and never truncates history. These are engineering admission constraints, not measured process-memory budgets or production capacity. Older over-limit state requires a separately reviewed recovery decision. Documents retain the separately documented 128 KiB content, 2 MiB per project, 100-document and 1,024 retained request-ID bounds. The HTTP parser retains its existing 10 MiB request limit; combined maximum-sized content is not claimed to be a qualified import profile.

Independent review found that 100 imported empty history batches plus a newly admitted active session would need 101 batches on export. Admission now reserves one of the same 100 portable batches whenever a project has active sessions. A project with 100 archived batches and no active sessions remains readable/exportable; a new draft is rejected before mutation. With 99 archived batches, active sessions export in the final batch. This derived compatibility constraint preserves every record and the original ceilings; it does not silently compact, drop or increase a budget.

Ordinary project access remains local and unscoped, even though the new routes require the existing reviewer boundary. Roster assertions and inline human attestations do not authenticate a production evidence producer or establish real-world independence. Legacy release gates still disclose their stored-record predicates; the new production-acquisition refusal prevents those predicates from authorizing release. No production trust adapter is implemented.

Native installation qualifications remain conditional on the documented toolchain, native directory ownership and Bun lifecycle conditions. The merged native directory resolver uses `fs.realpathSync.native`; the current Windows workflow exercises its actual default TEMP rather than imposing the older fixture's unaliased-path workaround.
