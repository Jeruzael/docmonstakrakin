## Concrete shared-authority implementation plan for integrator

Separate durable agent identity from session and client; issuance requires an authorized current sponsor, exact allowed scope and expiry. Store grant revision/revocation and unique client/session references. Reauthorize sponsor, agent, session, grant, project and task on every first attempt and retry. Sponsorship does not bypass explicit denies or protected self-project rules.
3. **HTTP/adapters:** `http.ts` currently maps every authenticated principal to `workspaceReviewerIdentity`; introduce a non-review session/display mapping before agents use it. Keep `identity.ts` and `workspaceVerificationPrincipal` HUMAN-only. Add a separately classified direct/local endpoint that delegates to the common action service; leave all 14 `BLOCKED_*` policies in `apiRoutePolicy.ts` intact. A direct client executes permitted product actions; it does not enable the existing privileged agent-run, secrets or repository routes.
4. **Admission/skills:** the same action service consults current versioned asset descriptions and required content receipts, with fixed public protocol discovery and authenticated scoped bootstrap read classes. Read-only is not a blanket receipt exemption. Receipt bindings include body/task/actor/client/session/policy/grant/skill revisions; retrieval is not proof of understanding.

Derive events, inbox/outbox and presence from acknowledged effects. Do not duplicate route-local business logic in a second action implementation. Keep business fact acceptance separate from delegated technical defaults.

### Persisted acknowledgment compatibility observations

At the inspected revision, SQL `operations` stores only `(operationId,snapshotRevision)` and any duplicate returns `WORKSPACE_OPERATION_REPLAY`. Worker startup requires exact SQL definitions and `user_version=1`. Backup observation pins schema hash `11db824c5cd6308dfca1fbd9e815a09cdb79c530ed889651edcbf3cecef2c909`; worker audit JSON currently has exactly six keys. A new table/column or arbitrary audit key therefore cannot be added without admitted compatibility changes.

A bounded, explicitly versioned audit event could hold operation/actor/scope/request/effect digests and returned revisions without changing SQL. It must be strictly admitted, atomically paired one-to-one with `operations`, and stay within backup's 4096-byte raw event limit. This changes the audit semantic format: old binaries reject the new event, so rollback requires documented compatibility. It cannot carry arbitrary response content, replace source authorization or infer missing legacy provenance. Full response/outbox storage is better handled by a versioned schema migration. This is an option for integrator assessment, not an implemented design or ratified capacity.

The preparation agent recommended lookup-before-handler, binding original request and resolved created-project scope separately, current target authorization even for create receipts, preserving historical versus current revisions, and fencing the in-memory projection until authoritative reload after uncertain commit.
